## Owner-adopted scope

The October 30 example is an **acceptance oracle**, not a hardcoded Elm workflow. The user approved **all three** universal additions, before declaring the Event/Date workspace functionally complete:

1. **A governed schedule decision** — compare source-qualified temporal claims, ask an authorized human where necessary, correct only through owning source writers, preserve original evidence and block only source-dependent future commitments.
2. **A one-sentence outcome record** — authorized ordinary Work completion includes a real state-change observation, with independent recorder/performer and evidence standing; do not equate a click with proof.
3. **A subject-related communication trail** — exact source relationship, correspondence provenance, transport status and actual reply/confirmation, without fabricating sent messages or copying them into an Event mailbox.

The three primary contracts are:
- `architecture/ATLAS_SUBJECT_DATE_SCHEDULE_RECONCILIATION_CONTRACT_V1.md`
- `architecture/ATLAS_ORDINARY_SHARED_WORK_OUTCOME_EVIDENCE_CONTRACT_V1.md`
- `architecture/ATLAS_SUBJECT_COMMUNICATION_SOURCE_RECEIPTS_CONTRACT_V1.md`

These extend, not supersede, the user-selected 10 workspace behaviors in the governing Version 3 build: adaptive Ledger Index; established vs proposed relationships; broad authorized ordinary collaboration with consequential permissions; notebook sentence builder without model dependence; evidence-gated completion; actor vs performer; responsibility offers vs attention; source relationships for communications; governed material conflict; and removal/unlink/retirement as distinct effects.

## Revised required build gates

**Packet 0:** finalize source/writer permission and provenance audit, including affected date consumers; keep the identified October 30 difference in the regression packet. Record actual source states instead of correcting data by inspection.

**Packet 1A:** protected clone + signed-session authorization of one read-only Ledger occurrence/operational assertion comparator. Neither successful custody CI nor a passing app helper test alone proves full DB authorization.

**Packet 1B:** first governing schedule correction path, including source versions, required approver, material conflict preflight, history and failed/partial outcomes. Only source-owned writers mutate; stay read-only if the writer is not yet lawful or source authority is unclear.

**Packet 2:** universal addressable Ledger subject Index and workspace with same source evidence and status as the bounded Date encounter. No duplicate Event and no contradiction hidden by the two entry paths.

**Packet 3A:** collaborative ordinary Work with one source item and Person attention, preserving the already released Event-work functions where lawful.

**Packet 3B:** evidence-backed Work result command and sentence-builder input. **No end-to-end shared Work Done acceptance until a nonempty outcome observation is required and source-accepted.** Existing historical bare-checklist results remain distinguishable.

**Packet 4:** independent personal attention / responsibility offer and acceptance; distinguish who may act, who is asked, who accepted, who performed.

**Packet 5:** source-owned communication relation/intent/receipt and authorized activity read, no inferred sent/delivered/received. Linked Work result evidence may point to receipts but never create them.

**Packet 6:** source-linked other reality (decisions, notes, dependencies, participant relationships) with explicit established vs suggested status.

**Packet 7:** universal temporal projections from Work, Communication, Person Life and Principal Clock with provenance/coverage. Use source law; schedule remains a read lens.

**Packet 8:** GIS/Place and resource capacity / booking conflict and write-time guards; all Day/Week/Month/Subject consumers use same identities and provenance.

**Packet 9:** three separately authenticated People, unrelated Ledger, at least two events on the same date, owner-vs-shared source privacy, mailbox permission denial, completion/reopen and cross-view state equality; retire legacy duplicate/employee-only pathways through reviewed releases.

The original ten numbered program packets remain; the A/B splits define **within-packet release gates**, not more parallel universes of source identity.

## Hard launch criteria for the October 30 proof

All of these must hold *together* before describing the demonstration as fully working:

1. Exact canonical Event is reachable through Ledger Index and the date without an alias duplication.
2. Both schedule claims are visible as source-qualified differences; an authorized decision/correction mechanism exists or state explicitly remains unresolved and dependent commitments are blocked selectively.
3. Authorized Persons can add, see, direct attention to and record outcomes on the same ordinary Work without an employee seat. Actual performer is not guessed from recorder or assignee.
4. Marking Book Music Done uses a sentence describing an outcome, which remains a **claim** unless confirmed by source-evidenced booking.
5. Exact communication composed from this subject retains an authorized subject relation; outbound provider status and actual reply are readable at the permitted privacy scope. No send receipt = no assertion of sent.
6. A previously sent invitation becomes a historical source fact even if schedule changes; follow-up is a distinct Work/communication action.
7. All actions keep correct actor, source ID, timestamp and history; replay/retry does not make duplicate Work, messages, commitments or Event identity.
8. Views are consistent, partiality/unknown source coverage is visible, and all negative authorization tests pass.
9. An unrelated Ledger proves no farm/Event-specific code path is required.
