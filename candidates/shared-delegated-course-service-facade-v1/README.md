## Credential issuance and durable admission (held)
The narrow service-only issue wrapper accepts the SHA-256 of a separately generated high-entropy bearer after the exact signed grant exists. It checks current owner/carrier/source scope, finite duration and explicit approval policy, then calls the existing credential issuer. It fixes expiry to the grant, marks the pilot credential, and reuses an exact retry; it denies any second active credential. Never supply a bearer or its hash in chat, commits, issue text, or logs. No generic credential issuance via plugin. No provisioned records in this migration. The separate service-only admission function uses the credential row's existing metadata to atomically cap admissions at 12 per UTC minute. It rechecks current authority; invalid/revoked/non-pilot credentials return false. It does not replace canonical source authorization and is a per-credential limit, not a perimeter denial-of-service defense. Site-private secret delivery and perimeter admission remain independently required before enabling the public endpoint. Credential rotation for this pilot means revoke and explicitly reauthorize, not silently changing custody. All tests are fictional local only.
