This is **not a farm feature, new identity registry, Rulebook issuer or second Work engine**. It extracts genuinely universal conditions that every Rulebook domain must satisfy **before** a separately verified Subject-domain adapter may authorize a policy. Because source equivalence differs between physical beds, household objects, Events, learning resources and other Subjects, no domain gains admission from matching UUIDs, labels, inferred keys, a signed user, a nearby Ledger or evidence-string resemblance.

## Universal invariant

The common layer verifies all of the following simultaneously:

1. Exact organization, primary governing native Ledger and existing active Requirement ID.
2. Current first-party authenticated human Principal and the Ledger's authorized native root, using existing signed-source functions—not browser metadata, role strings, remembered governors or service keys.
3. Requirement already linked to a Reality Entity by an explicit source_object_type=reality_entity and canonical Entity ID, with bounded explicit needKey. No conversion of legacy Work or unadjudicated identity assertions.
4. Referenced Reality Entity already canonical with typed kind and declared Subject domain. A declared domain is **not** verified adapter permission.
5. Separate currently effective Subject **identity** and **condition** disclosures for that exact root, Ledger and Subject.

Success returns state=common_checks_only_not_admitted and **all authority flags false**: domainAdapterAccepted, independentSourceReviewAccepted, policyAdoptable, policyExecutable, workCreated, clockAdmitted, successorWorkCreated. It does not grant execution to authenticated, anon or service_role, and exposes no public wrapper. A common-success response is never a Rulebook adoption permission, original Work, consent receipt or scheduling trigger.
