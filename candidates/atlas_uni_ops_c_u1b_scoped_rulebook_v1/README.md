## Constructed

- `candidate.sql`: source-only immutable lineage of exact **property**, **native growing-object class**, or **one canonical Subject** decisions for an actual `atlas.rhythm_rules` + active farm binding. The owner must approve each source separately; no bulk adoption or reconstructed unknowns.
- Native root and signed session must still hold; primary governing Ledger and farm-crop Ledger custody must still be effective. Exact Subject actions/reads require separate current identity and condition disclosures.
- A class decision cannot authorize a new Subject disclosure. The latest Subject override wins over class, class over property. A paused/retired selected version does not fall back to an older active version; a paused property umbrella holds all children.
- Root-only per-Subject effective read emits `policyExecutable:false`, even when an approved status reads active. This does **not** establish work eligibility, named-season membership, physical condition, recipient capacity, Work creation or original Need satisfaction.
- `postconditions.sql`: disposable rollback-only structural, RLS, private-table and signed-public-wrapper checks. These are **authored only**; not run on RiverSong/PG17.

## Exact unresolved architectural issue

U1A's `atlas.governed_rulebook_versions_v1` is based on one existing `atlas.work_requirements` + exact canonical Subject and independently reviewed Foundry Event. This U1B adapter preserves a different previously recorded native source family (`atlas.rhythm_rules`) in `atlas.governed_farm_rulebook_scope_versions_v1`. It is **not yet a proven unified canonical Rulebook**. The original source identities, policy lineage, precedence and potential overlapping Need must be reconciled under **one governing Rulebook source registry/authority** before either lane can become executable. Creating two tables in an experimental held branch is not permission to run two competing policy authorities.

The native Rule label/cadence can be recovered without a new interview. Those fields do not alone establish all desired-outcome, physical-evidence or historical-season semantics. Unknowns must remain explicit rather than generating a policy from a short label.

## C-style development and test boundary

The first Elm weeding/restorative action still requires actually sourced physical condition, a farm-wide canonical Subject audit and independent nonfarm domain acceptance.
