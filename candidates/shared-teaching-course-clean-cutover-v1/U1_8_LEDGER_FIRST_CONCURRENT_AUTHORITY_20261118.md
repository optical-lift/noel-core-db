# U1.8 — Consistent Ledger-first institutional authority locks (HELD)

**Owner context:** One canonical Person/one Auth; independently admitted institutional Titus accounts; Atlas remains the universal first priority. This increment is a **cross-domain shared security/concurrency source correction**, not a new Product/role/license feature or customer migration.

**Outcome and scope:** The U1.3 manager-governor command and U1.4 root nomination, cancellation and voluntary relinquishment previously acquired a Reality root responsibility `FOR SHARE` **before** the exact institutional `ledger.ledgers` `FOR UPDATE`. The separately signed successor-acceptance command acquired the invitation, **then Ledger, then updated the same Reality root**. A manager command or root nomination running against succession could therefore wait on the Ledger while holding the root shared lock that succession needed to update—a genuine two-transaction PostgreSQL lock-order inversion. No unauthorized role grant was observed, but a deadlock or HTTP 5xx could interrupt the flow.

**Held changes:**

- [U1.3 manager command](./shared_titus_institution_manager_governance_candidate.sql) now locks exact, active canonical `ledger.ledgers` **first**, then independently verifies current root via `titus.require_institution_root_manager_governor_self_v1` under `FOR SHARE`. A retry still must pass current authority; source history remains immutable.
- [U1.4 root commands](./shared_titus_institution_root_establishment_candidate.sql) now lock the same Ledger before root `FOR SHARE` in nomination, unused-invitation cancellation and voluntary relinquishment. Cancellation keeps its invitation `FOR UPDATE` first, matching the separately signed successor acceptance's invitation → Ledger order. The root's source relation is never updated/deleted without the existing one-root, exact Ledger checks.
- [Static regressions](../../tests/test_titus_u1_local_signed_safety.py) inspect the four SQL commands and require the Ledger `FOR UPDATE` text to precede the root helper; no source migration, new special roles or prod grants.
- [Genuine local signed concurrency test](../../scripts/validate-titus-u1-gotrue-local-signed.py) races two GoTrue-authenticated PostgREST requests for the **same fictional institution**: root-authorized manager appointment against root-authorized relinquishment. Exactly one action must commit, the other must return `42501` unauthorized-source denial—not a PostgreSQL deadlock—and the final root/manager counts must be either (1,1) or (0,0). All earlier root, manager, recipient-consent, cancellation, stale-session, cross-Ledger and source-mapping checks remain in the full test.

**Important limits:** A single concurrent test plus a source-order assertion is **evidence, not proof that all possible races are safe**. Actual production-schema/roles restore and source trigger/security review remain behind the existing separate owner-gated protected workflow.
