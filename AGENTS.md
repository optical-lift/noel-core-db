# Operating instructions for future agents and conversations

Start here for any task touching this shared Supabase project (`zirqkouammpwxlqfbsvf`) or `optical-lift/noel-core-db`.

1. **Classify before writing**: ordinary Noel word definition, source-token anchor, evidence edge, verse composition, research note or interpretation = **private data transaction**, not a migration. Atlas business/ledger fact = Atlas data transaction. DDL/functions/views/triggers/grants/RLS = reviewed code migration. Cross-domain identity or publication surface = Shared structural contract.
2. Read `docs/DOMAIN_WORK_ISOLATION_V1.md` and `docs/NOEL_RESEARCH_OPERATIONS.md`; consult `schemas/OWNERSHIP.md` and `custody/release-lanes-v1.json` for specific release ownership.
3. **Never place founder-authored research material, personal records or private source SQL in a public PR, migration, fixture, issue, workflow log or attachment.** Use an approved protected store. Private-source custody is not yet solved: see `docs/PRIVATE_RESEARCH_SOURCE_CUSTODY.md` and issue #1435.
4. For Noel everyday research: write to existing `draft.noel_reality_*` tables in authorized, source-verified transactions; preserve original founder definitions and decision history; keep `propagates_realm=false` unless separately governed. Do **not** call `apply_migration` or add `supabase_migrations` receipts for content. Verify before/after counts and migration ledger unchanged.
5. For structural migrations: source-first in `noel-core-db`, use `noel_` for Noel, `atlas_` for Atlas, `titus_` for Titus, `wnph_` for publishing, `shared_` for common surfaces. Generate via reviewed canonical workflow, disposable schema clone, protected production release. Do not use direct production SQL to deploy machinery.
6. **Global custody stays strict** on canonical main/schedule/manual monitoring. PRs get report-only global visibility and scoped domain checks. Unclassified/Shared deficiencies still block impacted releases; a foreign-domain historical issue must not indiscriminately stop Atlas or Noel work.
7. Titus cannot read all Noel data merely because both live in Supabase. Research publication, identity binding, and permission are independently verified. Service-role transport is not authorization.
8. Work on Atlas and Noel may be provisional and messy **inside their own private workspaces**. Do not silently promote provisional findings to founder/production/public authority.
9. When scope crosses domains or calls for changing private research permissions, stop and state the concrete unmet approval instead of guessing or weakening guards.
10. Finish with links to reviewed source, CI verification, and explicit outstanding gates. Do not claim a branch or draft PR is merged/deployed until it is.
